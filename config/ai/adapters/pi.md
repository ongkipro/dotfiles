## Runtime adapter — Pi

- Runtime facts: this context arrives through the `pi()` shell wrapper as `--append-system-prompt`, followed by device-local `~/.config/ai-local/device.md` when present. Pi owns its models, providers, auth, and sessions. How you work the task is yours to choose; the core's boundaries and evidence rules still apply.
- Shared stack follows dotfiles: `config/pi/settings.json` owns package pins, the `reviewer` (Sol) and `oracle`/`advisor` (Carbon) overrides, and `/review`; `dotsync` applies it via `pi-9router-restore` (device-local copy). The device keeps its default model and extras. Adding or re-pinning a package is the review point for extension code. Details: `config/pi/README.md`.
- One MCP owner per device: Pi's built-in MCP extension and `pi-mcp-adapter` both register `/mcp`. A device that installs the adapter records `"extensions": ["-builtin:mcp"]` and `"defaultTools": ["+codemode"]`, because only the built-in extension turns codemode on by itself. Servers always come from `~/.pi/agent/mcp.json`, written by `ai-mcp-sync`.
- Install: Pi runs from the pi.dev managed install on every device, never `npm i -g`; migrate with `pi-managed-migrate`, update with `pi update`. Rules: `config/pi/README.md` § Installation.
- Review pairing: the reviewer never shares the implementer's model family (Opus/Sonnet → Gemini 4 Carbon or Sol; Gemini → Opus or Sol; Sol → Opus or Carbon); `/review` applies it, or pass the model to `reviewer`; never self-review.
- `/goal --tokens <budget> <objective>` works in the TUI only; its limits are not dollar caps.
- Pi has no dotfiles hooks. `cc-safety-net` is the Pi-side guard for destructive commands and secret-file reads. It does not replace the approval gates: production, secrets, and destructive actions still need Paduka Ongki's explicit approval. `pi update` routes through `pi-update-safe`.
