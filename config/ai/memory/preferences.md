- **Conversation** language: casual Bahasa Indonesia; technical terms stay English.
- **Repo content** language (different from conversation), matching the final dotfiles policy:
  - **dotfiles** → skills (`SKILL.md`), memory (`config/ai/memory/*`, `config/ai/project-memory/*`), & system docs all in **English** — these are AI-read artifacts, and English keeps programming terminology unambiguous.

- **UI & Design Invariant — Star Ratings**: Whenever rendering star ratings or review stars (in hero sections, PDPs, review cards, social proof), the star icon must always be **solid / filled** (e.g. `<svg viewBox="0 0 24 24" fill="currentColor"><path d="M11.525 2.295a.53.53 0 0 1 .95 0l2.31 4.679a2.12 2.12 0 0 0 1.595 1.16l5.166.756a.53.53 0 0 1 .294.904l-3.736 3.638a2.12 2.12 0 0 0-.611 1.878l.882 5.14a.53.53 0 0 1-.771.56l-4.618-2.428a2.12 2.12 0 0 0-1.973 0L6.396 21.01a.53.53 0 0 1-.77-.56l.881-5.139a2.12 2.12 0 0 0-.611-1.879L2.16 9.795a.53.53 0 0 1 .294-.906l5.165-.755a2.12 2.12 0 0 0 1.597-1.16z"/></svg>`), **never hollow, empty, or outline-only**. Color: a solid amber or brand hue that reaches ≥3:1 against its surface (WCAG 1.4.11): `#d97706` (3.18:1 on white) is the light-surface default; the old `#f59e0b` / `#fbbf24` / `#f5a623` fail on white (2.14 / 1.66 / 2.02:1) and are for dark surfaces only after measuring (`design-taste/scripts/contrast.py`, checked 2026-10-08).
- **UI & Design — Zero AI-Slop (quality rules fixed; style chosen per project by research)**:
  - **Decorative badge icons & Sparkles are AI slop**: NEVER use `Sparkles`, `lucide-sparkles`, magic stars, wands, or decorative mini badge icons inside kickers, buttons, filter dropdowns, toolbar controls, or section headers. They look like cheap generative AI slop. Use pure, crisp typography or authentic functional domain icons only (e.g. `Droplets` for hydration/formula, `Layers` for collections, `ArrowUpDown` for sorting, `Shield` for warranty/safety, `Truck` for shipping, `Box` for packaging).
  - **Shape language is a per-project research decision, not a house look** (owner decision 2026-10-08): choose radius, surfaces, gradients, and visual references from the surface type (`design-taste/references/surface-catalog.md`), inspected references, the brand, and the cross-project distinctness check (`design-taste` §2); record the choice and its evidence in the project's design artifact. Defaults when nothing has been decided: avoid bloated `rounded-3xl` containers, pill badges on everything, and pastel gradients used as decoration. Flat, sharp or micro-radius with architectural whitespace (Rhode, Aesop, SSENSE) is one valid direction for premium lifestyle brands, not the default for every site.
  - **No invented meters; no gimmicks by default**: NEVER invent arbitrary percentage progress bars or scores (e.g. "35% Recovery Barrier", "70% Surface Refinement") — numbers shown must be real. Physical-object simulation (pushpins, taped paper, tilted memo cards, corkboards) is avoided by default and allowed only when the researched concept for that brand deliberately calls for it. Real sequences (timelines, steps) read as clear linear progressions with genuine factual copy; their visual form follows the project's direction.
- **UI & Design Default — Section transitions**: default to whitespace, spacing, and background shifts between sections rather than horizontal rules (`border-t`, `border-b`, `<hr>`) above or below hero and footer. A divider is allowed when the project's researched direction calls for it (e.g. an editorial or broadsheet layout) and the design artifact records why.
- **UI & Design Invariant — No Contact-CTA Spam (WhatsApp)**: At most ONE WhatsApp/contact call to action per page, placed after the user's task is done (tool result, end of article/product, form submit). NEVER in header, menu, hero, sticky bars, floating buttons, pop-ups, or repeated per list item. Footer may list the number as plain contact text. Use a secondary-style button with a monochrome icon, not brand-green WhatsApp styling. Sharing uses the native share sheet, not a second WhatsApp icon.
- **UI & Design Invariant — Article Metadata & Tags (Clean Editorial, Anti-Overspace, No Heavy Chips)**:
  - **Metadata, Not Buttons or Cards**: Article tags are taxonomical metadata, NEVER primary action buttons, status pills, or framed cards. Do NOT wrap individual tags in heavy container frames, bordered boxes, or filled card chips (e.g. `bg-tint`, borders, rounded pill badges).
  - **Clean Inline Typographic Flow**: Tags must render as a clean, compact inline typographic list: prefixed with a crisp, uppercase label (`Tag:` in muted or soil accent color), followed by natural text links with a subtle `#` hashtag prefix. Interactivity uses subtle color transition to brand color and text underline (`hover:underline underline-offset-4`), keeping the reading experience calm and editorial.
  - **Strict Anti-Overspace (No Double Margins & No Inflated min-height)**:
    - NEVER apply isolated touch-target buttons `min-h-[44px]` to inline tag links. Forcing 44px min-height on multi-tag wraps inflates the tag block vertically to 120px–150px+ of dead space on mobile screens. Use compact line-height with minimal padding (`py-0.5` to `py-1`).
    - Account for the natural `margin-bottom` of prose closing paragraphs (`p:last-child`). Never stack large top margins (`mt-8`, `mt-10`) on top of prose bottom margins; keep the top spacing tight (`mt-3` to `mt-4`) and bottom rhythm balanced so the tags feel like a natural paragraph footer rather than an abandoned floating element.


- **SEO Invariant — Title & Meta Description Length (all websites, owner rule 2026-09-30)**: final rendered `<title>` is **55–70 characters including spaces and the brand suffix** (`{Page title} - {Brand}`; home may omit the suffix); meta description is **120–155 characters including spaces**, ends with a full stop. Separator is ` - ` (or `:` inside a title), **never `|` or `—`**. Pad a short title/description with related, natural keywords (topic, commodity, place, intent), never with hype words ("Rahasia", "Ampuh", "Tuntas", "100%") or keyword lists. Generated titles (tags, hubs, pagination) use a fit-to-range helper, and the build check fails outside the ranges. Every page also carries `<meta name="author">` (article author, otherwise the brand/publisher name) and `<meta name="publisher">`; articles add `article:author` and `article:publisher`, and JSON-LD links `author` → Person and `publisher` → Organization with a raster logo. Reference implementation: agritani `src/lib/seo.ts` `fitText()` + `scripts/check-seo.mjs` (DEC-022, T-45).
- **SEO Invariant — Images: WebP + Keyword ALT (all websites, owner rule 2026-10-01)**: every page image is **WebP** (SVG for icons; only platform-required PNGs such as OG images and `apple-touch-icon.png` stay PNG). Every content `<img>` has a descriptive ALT of **10–125 characters** containing the page's keyword (commodity/topic/product + what the image shows), never empty, a lone generic word ("gambar", "foto", "ilustrasi"), or a keyword list. Dynamic pages build ALT from their data (e.g. `Ilustrasi {commodity}: {title}`, `Kemasan {product}, {role}`). A build check fails on a non-WebP source or a bad ALT. Reference implementation: agritani `src/lib/image-alt.ts` + `scripts/check-images.mjs` (T-54).
- **SEO Invariant — Public URL slugs (all websites, owner rule 2026-10-28)**: a public page slug is short, readable words taken from the title (lowercase ASCII, hyphens, ≤ 60 characters at a word boundary), **never a UUID, hash, database id, random suffix or long code**. Uniqueness comes from a stored unique slug column with a short numeric suffix on collision; a renamed or legacy URL answers one 308 redirect to the current slug, and sitemap, canonical, JSON-LD and feeds always use the current slug. Admin URLs use short numeric ids, never UUIDs; the UUID stays inside APIs and the database. Project-specific scheme and exceptions: [[99ribu-url-slugs]].
- **Cloudflare Default — Asia-Pacific placement (Indonesia/SEA web projects, owner rule 2026-11-02)**: create D1 and R2 with `--location apac` and Durable Objects with `locationHint: "apac-se"`; leave Worker `placement` unset for edge-only Workers and point it at the backend's region (e.g. `aws:ap-southeast-1`, `gcp:asia-southeast2`) when one backend dominates. Hints are latency, not residency: Cloudflare has no Asian jurisdiction, and visitor PoP (CGK vs SIN) follows ISP peering, not settings. Details and migration of existing resources: `cloudflare` skill `references/apac-placement.md`.
- **UI & Design Invariant — Icons**: use inline SVG copied from the Lucide set (one stroke style, `aria-hidden`, `currentColor`), not an icon React/JS package, on static or non-React sites; functional icons only (no decorative sparkles/badges). In an existing React app, `lucide-react` is acceptable when already installed.
- **Meta Ads Invariant — Anti-Boncos & Profit-First Scaling (owner rule 2026-11-05)**:
  - **Lowest Cost Ceiling (Rp 300K–400K)**: Never scale Lowest Cost campaigns (`LOWEST_COST_WITHOUT_CAP`) to Rp 1 Juta+/day. Pacing rush causes Meta to bid into unqualified auctions and spikes CPR. Keep Lowest Cost capped at **Rp 300.000 – Rp 400.000/hari** for tight, profitable delivery.
  - **Scale via Bid Cap & Min ROAS**: Budgets of Rp 1 Jt – Rp 2 Jt+ belong strictly to **Bid Cap** (`LOWEST_COST_WITH_BID_CAP`) or **Target ROAS** (`LOWEST_COST_WITH_MIN_ROAS`). Hard cost constraints (e.g. bid cap Rp 34K–46.5K or min ROAS 4.0x) act as automated algorithmic brakes that prevent boncos while capturing volume.
  - **Hard Stop-Loss Rule (Content Ad Level — Owner Rule 2026-11-06)**:
    - Konten iklan (ad-level) di semua produk kita (HKM 1, 2, 3): Batas toleransi testing adalah **Rp 50.000 per konten ad**.
    - Jika satu konten ad sudah menghabiskan budget **≥ Rp 50.000 dengan 0 lead / 0 purchase** ➔ **BARU OFF-KAN (PAUSE) kontennya**.
    - Jika spend masih **< Rp 50.000**, jangan dimatikan terlalu dini; berikan ruang bagi algoritma untuk menjemput lead hingga menyentuh batas 50K.
    - Jika konten menghasilkan lead/purchase sebelum atau di sekitar 50K (seperti SARATOGA, BENSU, AUSSIE), biarkan tetap ON sebagai winning content.
    - Prune adset duplikat di CBO yang menyedot budget tanpa hasil (konsolidasikan ke adset single broad pemenang).
  - **Comment Hygiene**: Immediate hide (`is_hidden: True`) on negative comments/complaints; immediate warm reply directing to the specific product Landing Page with COD & promo messaging on positive inquiries.
  - **Autonomous Execution**: When leakages (inflated budgets, bleeding adsets, choked spend caps, negative comments) are detected, execute fixes directly via `dotads-meta` / Meta Marketing API with the singular goal: zero boncos, maximum profit.
  - **Shopee Collaborative Ads (CPAS `1-1-1` Direct-to-App Invariant — Universal & Dynamic Across All Niches/Products, Owner Rule 2026-11-07)**:
    - **Scope (Dynamic, Never Locked to One Brand or Niche)**: Applies universally to all CPAS accounts, all product niches (beauty, fashion, FMCG, herbal, F&B, mom & baby, home living, electronics, automotive, etc.), and all price/AOV tiers. Structural, measurement, and deep-link rules are fixed invariants; budgets, stop-loss thresholds, product sets, demographics, and copy adapt dynamically to each brand's catalog and unit economics.
    - **CPAS Purchase Conversion Column Law (`catalog_segment_*` + `7d_click` vs `1d_view`)**:
      - On Shopee CPAS accounts, **99.94%+ of real purchase conversions live in `catalog_segment_actions` (`omni_purchase`, `app_custom_event.fb_mobile_purchase`) and `catalog_segment_value` (`omni_purchase`)**, NOT in ordinary `actions`/`action_values` (which are often `0` in 7d/30d windows on CPAS accounts). Always query `--metric-profile cpas_v1` with `action_attribution_windows=['1d_click','7d_click','1d_view','default']`.
      - Always separate **`7d_click` (Click-Through Purchase Conversion)** from **`1d_view` (View-Through Purchase Conversion)**: in Retargeting (`RMK`), **80%–86% of `catalog_segment_actions:omni_purchase` is `1d_view`** (impression-only credit on warm Shopee cart shoppers), whereas in Cold Prospecting (`NV`), `CPA_7d_click` can be **25% cheaper** than in `RMK`. Evaluate placements and creatives primarily on `catalog_segment_actions:omni_purchase` (`7d_click` CPA/ROAS + Total CPA/ROAS).
    - **Architecture (`1-1-1` Format Isolation)**: `1 Campaign (CBO, OUTCOME_SALES, GUIDED_CREATION, LOWEST_COST_WITHOUT_CAP)` → `1 Ad Set` → `1 Ad`. Default to `CAROUSEL_DPA` (`carousel_images_multi_items`, 5–10 cards) or `SINGLE_IMAGE_DPA` (`show_multiple_images: false`) for direct-to-PDP efficiency; if testing a Hero KOL/demo `COLLECTION_VIDEO` for cold prospecting, isolate it in its own dedicated `1-1-1` campaign (never mix `COLLECTION_VIDEO` with `CAROUSEL_DPA` in the same ad set, and avoid static `COLLECTION_IMAGE`).
    - **Channel & Placement Law (99.999% Direct-to-App)**: Across Rp 327.13M audited Indonesia Shopee CPAS spend (`87,830` `catalog_segment_actions:omni_purchase` orders / Rp 5.29B GMV), **99.999% of purchases (`87,829 / 87,830`)** occurred via `app_custom_event.fb_mobile_purchase` (Shopee Mobile App SDK) and **0.001% (`1`)** via `offsite_conversion.fb_pixel_purchase` (Web Browser). Enforce `device_platforms: ["mobile"]`, `publisher_platforms: ["facebook", "threads"]`, `facebook_positions: ["feed", "facebook_reels"]` (#1 and #2 in `7d_click` Purchase CPA/ROAS), and `threads_positions: ["threads_stream"]`.
    - **100% Exclusion of Instagram & Audience Network**:
      - **Instagram (`0%` Budget)**: Instagram WebView intercepts Shopee universal links (`https://shopee.co.id/universal-link/product/...`) into the Instagram In-App Browser (IAB) instead of launching the native Shopee App. Meta logs a false-positive `app_site_visit` while actual Shopee SDK arrival (`app_custom_event.fb_mobile_content_view`) collapses to **0.83% on IG Feed Carousel** and **0.52% on IG Stories**, making Cold Prospecting (`NV`) `CPA_7d_click` **2.2x–5.3x more expensive** (`Rp 46,579` on IG Feed, `Rp 44,375` on IG Stories vs `Rp 8,727` on FB Reels and `Rp 14,677` on FB Feed).
      - **Audience Network (`0%` Budget)**: Accidental banner/rewarded-video clicks produced **0.012% `InApp_VC`** (4 views from 32,506 clicks; 99.99% bounce), `0.22%` `CVR_7d_click` (`0.63x` `ROAS_7d_click` loss in `NV`), and 96.9% `1d_view` attribution pollution.
    - **Deep-Link & Dynamic Template Contract**: Creative must set `applink_treatment: "deeplink_with_web_fallback"` (never `"automatic"`, which leaked 65–72% of FB Feed clicks to browser), `template_url_spec` bound to the marketplace App ID (Shopee ID `config.app_id: "957549474255294"`, Android `com.shopee.id`, iOS `959841449`), `url_tags: "utm_source=facebook-ca&utm_medium=seller"`, `name: "{{product.name}}"`, `description: "{{product.current_price strip_zeros}}"`, and clean plain-Latin primary text adapted to the niche (no Unicode mathematical fonts).
    - **Forensic Measurement Rule**: Always verify true Shopee App arrival via `InApp_VC` (`app_custom_event.fb_mobile_content_view / link_click`, target `≥ 25%`) and `catalog_segment_actions` (`omni_purchase` & `app_custom_event.fb_mobile_purchase`, split by `7d_click` vs `1d_view`); never rely on ordinary `actions`, `app_site_visit`, or `omni_view_content` alone.
    - **Dynamic Budget, Stop-Loss, & 3-Pillar Product Set Scaling (Adaptive to Niche & Unit Economics)**:
      - **Dynamic `1-1-1` CBO Budget**: Set initial daily budget to `max(Rp 25.000, 1.5x–2.5x Target_CPA)` (Rp 25.000–35.000/day for low/mid-ticket AOV ≤ Rp 150K; scaled proportionally to `1.5x–2.5x Target_CPA` for higher-ticket niches while staying below the Rp 300K–400K Lowest Cost ceiling). Scale horizontally by duplicating winning `1-1-1` units.
      - **Dynamic Stop-Loss Gates**: Pause at `Spend ≥ max(Rp 45.000, 1.5x Max_CPA)` with `0` `catalog_segment_actions` `app_custom_event.fb_mobile_add_to_cart`, or `Spend ≥ max(Rp 75.000, 2.5x Max_CPA)` with `0` `catalog_segment_actions` `omni_purchase` (`7d_click`).
      - **Dynamic 3-Pillar Product Sets & `[PROS]`/`[RMK]` Split**: Adapt catalog sets to any store into Pillar A Hero (`2–5` top SKUs with `4.8+` rating, ~50% budget), Pillar B Full/Category Catalog (`≥ 5` active SKUs for cross-selling, ~30% budget), and Pillar C Bundle/Multi-Pack (`2–4` high-AOV bundle SKUs, ~20% budget). Keep `[PROS]` (Broad Mobile ID adapted to niche age/gender) and `[RMK]` (View/ATC `14–30d` excluding Purchase `30d`, window matched to niche buying cycle) in separate `1-1-1` campaigns.
