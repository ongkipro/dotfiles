# Memory: Two-way communication preference

Owner preference, 2026-10-29. Advisory; current task and repository contracts
remain authoritative. Methodology belongs to `writer`, especially
`references/two-way-localization.md`.

- Interpret informal Indonesian, obvious typos, and mixed technical vocabulary
  using the active conversation. Preserve negation and accepted scope. Resolve
  ambiguity only when it changes the action, target, authorization, or outcome.
- For a complex request, break down the intended result, constraints, steps,
  and proof needed. Research uncertain technical facts, not the owner's intent.
- Explain back in natural Indonesian with practical consequences and a useful
  example when needed. Avoid jargon-only answers and ritual "do you understand?"
  questions. A focused check-back is useful for consequential ambiguity, not
  required after every message.
- Keep artifact language separate from explanation language. When another
  language is requested, adapt to its locale, audience, channel, and established
  register rather than translating Indonesian sentence patterns literally.
  Do not infer communication preferences from nationality alone.
- An ecommerce project must retain its accepted operational depth; consulting
  a simpler storefront does not authorize simplifying away its workflows.
- Learn from explicit corrections within the session. Propose durable updates
  only for scoped, verified or owner-confirmed preferences through the reviewed
  learning loop; never infer personality or store raw private dialogue.
