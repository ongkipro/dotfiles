Repository contracts and delivery evidence

New projects receive explicit authorities for requirements, task state, decisions, architecture, build history, observability, and release readiness. The append-only .delivery/ ledger binds a run to its task, requirement, resolved route, verification, result, and provenance.

project-check
  -> delivery-ledger verification
  -> migration / rollback checks
  -> production-gate
  -> explicit deploy approval
  -> release-check

Passing a gate records evidence; it does not grant production authority. STATUS.md remains the live workflow-state owner, and deployment still requires explicit approval.

Canonical sources: skills.md, ai-memory-sync.md, runtime-commands.txt, and README.md.
