Architecture & Orchestration

The kernel keeps shared policy, project truth, advisory memory, capabilities, and runtime routing separate. Each layer has one owner, so a convenient summary cannot silently replace executable state.

Authority precedence

Use the highest available source for the claim being made. Memory and historical documents help recover context; they never override current repository state or observed behavior.

Risk-aware OMP orchestration

OMP remains the session and context owner. It classifies the work itself—not the file extension—then keeps ordinary work local or dispatches a bounded specialist when visual capability, independent judgment, external source research, or difficult reasoning justifies it.

R0Mechanical
R1Bounded
R2Interacting
R3Correctness-sensitive
R4Costly to reverse
  • Specialists own methodology. Routing selects who executes; skills define how the work is done.
  • The parent retains integration. Delegation never transfers final context, conflict resolution, or verification ownership.
  • Fallback preserves task ownership. Provider availability may change the worker, not the required contract.
  • Approval remains human. Broad tool permission does not authorize destructive, production, secret, or system-wide actions.
