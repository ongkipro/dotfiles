## Main problem

The account looks like an active workbench, not yet a curated professional portfolio.

A visitor should understand within 5 seconds:

> Ongki builds AI-native ecommerce systems, Shopify/headless websites, SEO automation, and digital growth infrastructure.

## Priority 1 — Create GitHub profile repo

Create a public repository:

```txt
ongkipro/ongkipro
```

Then add the README draft from:

```txt
docs/github-profile-readme-draft.md
```

This will become the front door of the GitHub account.

## Priority 2 — Pin 6 repos

Recommended pinned repo categories:

1. **AI Operating System**
   - `dotfiles`
   - Purpose: flagship technical repo.

2. **Personal brand**
   - `ongki.pro`
   - Purpose: portfolio/business identity.

3. **Best client/service website**
   - Choose one clean repo, not multiple versions.

4. **Best ecommerce/headless project**
   - Choose the most complete Shopify/Astro project.

5. **Best affiliate/SEO system**
   - Choose the cleanest affiliate/content automation repo.

6. **Best Cloudflare/Astro deployment**
   - Choose one production-quality technical showcase.

## Priority 3 — Archive or rename duplicate repos

Repos that look like duplicates/version experiments should be reviewed:

- `Jasa-Website`
- `Jasa-Website-v2`
- `jasa-website-v2.1`
- `jasa-website-v2.11`
- `Halona-V2.1`
- `halona-v21`
- `HLTest`
- similar short or unclear repo names

Recommended policy:

- Keep one canonical repo per project.
- Archive old attempts.
- Rename unclear repos into clear, kebab-case names.
- Add README to any repo that stays public.

## Priority 4 — Naming standard

Use kebab-case:

```txt
project-name
commerce-portal-os
kiheute-content-system
shopify-headless-store
astro-affiliate-portal
cloudflare-worker-api
```

Avoid:

```txt
Project-v2
project-v2.1
HLTest
new-final-final
```

## Priority 5 — Standard README template for important repos

Every serious public repo should have:

```md
# Project Name

## What it does

## Why it exists

## Stack

## Architecture

## Features

## Setup

## Screenshots / Preview

## Status

## Lessons learned
```

## Priority 6 — Dotfiles as flagship repo

Improve `dotfiles` until it represents the core operating system:

- add `doctor.sh`
- run `security-check` before push
- add gitleaks/pre-commit option
- add memory graph `index.yaml`
- remove personal email references unless needed
- replace stale `ongki5758` references with `ongkipro`
- add architecture diagram
- document AI CLI memory routing

## Priority 7 — Public/private policy

Keep private:

- credentials
- client projects with private business data
- unfinished experiments that reveal poor quality
- AI memory with sensitive personal/client details

Make public:

- polished portfolio repos
- reusable tools
- sanitized templates
- educational examples
- dotfiles only if secrets are fully removed and memory is sanitized
